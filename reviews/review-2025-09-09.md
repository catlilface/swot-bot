## Executive Summary

The project is a well-structured **microservices monorepo** using `uv`, `dishka` DI, RabbitMQ event-driven pipeline, and Pydantic v2 contracts. Code quality is generally good — clean separation of domain / adapters / providers, meaningful unit tests with hand-written stubs, JSON-structured logging, and health endpoints per service.

However, **three P0 blockers** make the current codebase unsafe and non-functional for its core use case:

1. **Inverted downloader routing** — all platform URLs (YouTube, Yandex Disk, VK, etc.) are routed to a naive HTTP passthrough instead of `yt-dlp`, so actual media is never downloaded.
2. **Path traversal** — RabbitMQ messages carry file paths that are used without containment checks, enabling arbitrary file reads and deletion.
3. **DI resolution bug** — `JobRegistry` protocol is not properly wired in Dishka, which will cause runtime container failures.

Additionally, there are **≈15 P1 findings** covering async safety, signal handling, Docker security, and documentation gaps.

## P0 Blockers (must fix before release)

### P0-1. `SourceRouter` routes platform URLs to `DirectHttpAdapter` instead of `YtDlpAdapter`
- **File:** `services/downloader/src/swot_downloader/adapters.py:82–93`
- **Impact:** Downloads from YouTube, Yandex Disk, Google Drive, VK, Rutube will fetch HTML/error pages instead of media. Core pipeline is broken for all listed sources.
- **Fix:** Invert the logic — route known platform hosts through `YtDlpAdapter` and use `DirectHttpAdapter` for literal media URLs.

```python
if self._is_platform_url(source.url):
    return await self._yt_dlp.download(source, dst_dir)
return await self._direct.download(source, dst_dir)
```

---

### P0-2. Path traversal via RabbitMQ message fields in Analyzer and Bot
- **Files:**
  - `services/analyzer/src/swot_analyzer/service.py:48,50` — `Path(message.base_dir)` and `Path(message.srt_path)` used unchecked
  - `services/bot/src/swot_bot/handlers.py:96` — `Path(msg.summary_path)` used unchecked
- **Impact:** A compromised/malicious broker producer can read arbitrary files outside the artifacts volume (`/etc/passwd`, `../../etc/passwd`).
- **Fix:** Normalize and enforce containment under the configured `artifacts_dir` before use:

```python
resolved = Path(message.base_dir).resolve()
if not str(resolved).startswith(str(self._artifacts_dir.resolve())):
    raise ValueError("path traversal detected")
```

---

### P0-3. Arbitrary file deletion via untrusted `media_path` in Transcriber cleanup
- **File:** `services/transcriber/src/swot_transcriber/service.py:90`
- **Impact:** `Path(media_path).unlink(missing_ok=True)` trusts a broker message path. Arbitrary file deletion is possible.
- **Fix:** Validate containment under `media_dir` or `artifacts_dir` before unlinking.

---

### P0-4. `RegistryProvider` returns concrete `InMemoryJobRegistry` instead of `JobRegistry` Protocol
- **File:** `packages/bus/src/swot_bus/providers.py:52`
- **Impact:** Dishka resolves dependencies by annotated return type. `InMemoryJobRegistry` is a concrete class that does **not** structurally satisfy the `JobRegistry` Protocol annotation used by all services. Container resolution will fail at runtime.
- **Fix:** Change the return annotation from `InMemoryJobRegistry` to `JobRegistry`.

```python
@provide(scope=Scope.APP)
def registry(self) -> JobRegistry:
    return InMemoryJobRegistry()
```

## What Is Already Good ( preserve )

- **Monorepo structure**: Clean `uv` workspace with no circular package dependencies (`contracts` → `observability`/`bus` → services).
- **Event-driven pipeline**: Explicit Pydantic v2 message types with discriminators; safe serialization/deserialization.
- **Tests**: Meaningful hand-written stubs (`StubRouter`, `StubExtractor`, etc.) and an end-to-end pipeline test via `FakeBus`.
- **Security (partial)**: ffmpeg uses `create_subprocess_exec` with list args (no shell injection); yt-dlp uses Python API (no CLI injection).
- **Observability**: `structlog` with JSON renderer + `trace_id` propagated across RabbitMQ headers; health endpoints on every service.
- **CI**: Runs pre-commit, ruff, pytest, and import sanity check on PRs.
- **Docker**: Multi-stage builds with `uv` cache mounts and `PYTHONUNBUFFERED=1`.
- **Error paths**: All services catch exceptions, publish `JobFailed`, and update registry status to `FAILED`.
